# Driver Mutation Review: TP53 Example

This folder documents, with patient-data-safe example code, how driver mutations such as `TP53` were identified from the tumour-normal WES outputs.

The real project used somatic calls generated by `nf-core/sarek 3.8.1` from matched tumour-normal whole-exome sequencing (WES). The relevant variant callers were:

- `Mutect2`
- `Strelka`

The downstream review used VEP-annotated somatic variant tables. Real patient-level VCF, MAF and TSV files are intentionally not included in this repository.

## What Was Done For TP53

At a high level, TP53 mutation review followed this logic:

1. Start from tumour-normal somatic SNV/indel calls generated by `nf-core/sarek`.
2. Use VEP annotations to identify variants whose annotated gene symbol is `TP53`.
3. Keep protein-impacting coding variants for mutation interpretation, especially:
   - `missense_variant`
   - `stop_gained`
   - `frameshift_variant`
   - `splice_acceptor_variant`
   - `splice_donor_variant`
   - `start_lost`
   - `stop_lost`
   - `inframe_deletion`
   - `inframe_insertion`
4. Treat high-confidence somatic calls, especially `PASS` calls, as the strongest evidence.
5. Retain lower-confidence caller rows separately for review, but do not automatically count every low-confidence row as a validated TP53 mutation.
6. Integrate TP53 somatic mutation evidence with other alteration layers, including copy-number loss/gain and germline-context flags, to create a patient-level `TP53_alteration` summary.

In the manuscript, the phrase `TP53 alteration` refers to this integrated patient-level field. It is broader than `somatic TP53 mutation` because it can include non-somatic or copy-number-only TP53 flags when those were retained in the integrated molecular summary.

## Input Format

The example script expects a tab-separated VEP-annotated somatic variant table with at least these columns:

| Column | Meaning |
| --- | --- |
| `patient_id` | Patient or tumour identifier |
| `caller` | Variant caller, for example `mutect2` or `strelka` |
| `chrom` | Chromosome |
| `pos` | Genomic coordinate |
| `ref` | Reference allele |
| `alt` | Alternate allele |
| `filter` | Caller filter status, for example `PASS` |
| `gene` | VEP gene symbol |
| `impact` | VEP impact, for example `HIGH`, `MODERATE`, `LOW`, `MODIFIER` |
| `consequence` | VEP consequence string |
| `amino_acids` | Amino-acid change if available |
| `protein_position` | Protein position if available |
| `clin_sig` | Clinical significance annotation if available |
| `existing_variation` | Known variant IDs, such as dbSNP/COSMIC IDs |
| `normal_dp` | Normal depth |
| `tumour_dp` | Tumour depth |
| `normal_af` | Normal allele fraction |
| `tumour_af` | Tumour allele fraction |

Column names can be adapted with light editing if your VEP export uses different names.

## Run The Example

```bash
python identify_tp53_mutations_example.py \
  --variants path/to/vep_annotated_somatic_variants.tsv \
  --out-prefix results/example_tp53
```

The script writes:

- `example_tp53.tp53_variant_rows.tsv`: all TP53 variant rows, including low-confidence rows for audit.
- `example_tp53.tp53_patient_summary.tsv`: one row per patient with a conservative TP53 somatic mutation status.

## How To Interpret The Output

The patient-level `tp53_somatic_mutation_status` column is intentionally conservative:

- `TP53_somatic_coding_PASS`: at least one `PASS` protein-impacting TP53 variant was found.
- `TP53_somatic_coding_review`: protein-impacting TP53 variant evidence exists, but all such rows are non-`PASS` or otherwise require review.
- `TP53_no_coding_somatic_variant_detected`: TP53 rows may be absent, synonymous-only, UTR-only or non-coding/non-protein-impacting.

This output is a driver-review aid, not a clinical report. Low-confidence rows, FFPE artifacts, tumour purity, local coverage and normal-sample evidence should be reviewed before making biological claims.

## Relation To The Manuscript

The manuscript reports both driver-gene mutation evidence and broader integrated alterations. For TP53, the final integrated table counted any non-`not_detected` value in `TP53_alteration` as a TP53 alteration. That is why the broad TP53 alteration count can be larger than the strict somatic TP53 mutation count.
